# fix: default Unix domain socket authority to localhost

An omitted UDS authority now resolves to `localhost` instead of the socket path. Explicit authority values, including an explicitly empty value, pass through unchanged. Endpoint addresses, service configuration and pull-mode resolution retain their existing behavior.

Resolver regressions cover absolute and relative paths, spaces and percent characters, repeated resolution, explicit host/port and IPv6 authority overrides, and explicitly empty authority. They exercise the public factory and default resolver registry without starting sockets or servers.

## Validation

Validated from fork `bb91b124b6f20cf82edec4b379bdcf8838f98343` on Apple Swift 6.4 using four jobs and one retained scratch directory. Restoring only the old resolver implementation while retaining the new regression produced RED: one test failed exactly four authority assertions, one for each path. The candidate passed all 19 resolver tests, then all 429 core cases (373 XCTest and 56 Swift Testing). Wall times were 76.281 seconds for RED including the fresh dependency build, 4.224 seconds for resolver GREEN, and 7.322 seconds for the complete core run.

The complete HTTP/2 run exposed one remaining path-derived authority expectation in `testAuthorityUDS`; it now verifies `localhost` through a real client/server exchange. The original failure log is preserved. The corrected case passed, followed by the complete HTTP/2 suite: 89 XCTest cases passed, one pre-existing Vsock case was skipped because Vsock is unavailable on this host, and 21 Swift Testing cases passed. Wall times were 6.895 seconds for the focused run including the 2.94-second test-only rebuild and 2.685 seconds for the complete suite using the existing build. The skip is an applicability limitation, not a successful Vsock test.

Focused Swift formatting and the repository license-header check passed. Raw logs, source hashes, exact commands and the actual resolved dependency graph are retained in the goal's `upstream-audit` directory. No live tonic interoperability or released artifact is claimed.
